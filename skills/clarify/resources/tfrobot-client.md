# Clarify — tfrobot-client 专属指南

> 通用流程参见 SKILL.md 主文件。

## 项目上下文

- **类型**：Computer 跨平台桌面客户端
- **语言/工具链**：Rust + TypeScript，Tauri 框架
- **定位**：A2C-SMCP 体系的 Computer 端桌面应用——在用户机器上运行，接收 Agent 的指令并操控本地环境

## 影响视角定义

tfrobot-client 的「终端用户」是桌面应用的使用者，而它的「开发者」和「外部集成方」合二为一。使用**定制二视角**：

| 视角 | 本项目中的含义 |
|------|---------------|
| **终端用户** | 在桌面端使用 tfrobot-client 的人——他们通过这个客户端让 AI Agent 操控本地环境 |
| **客户端开发者 / 插件开发者** | 开发和维护客户端本身、或为客户端编写插件的人——他们面对 Tauri IPC、跨平台差异、桌面集成 |

## 关键用户画像

### 画像 1：桌面端终端用户
- 场景：启动 tfrobot-client，连接 Agent 系统，让 AI 操控本地文件、执行命令、操作应用
- 敏感点：启动速度、系统资源占用（内存/CPU）、托盘/通知等桌面集成体验、平台原生感
- 典型问题：「客户端一直在后台跑着，风扇开始转了——是在做什么持续操作还是内存泄漏？」

### 画像 2：客户端/插件开发者
- 场景：为 tfrobot-client 开发新功能或插件，处理 Tauri IPC、前端-后端通信
- 敏感点：Tauri API 的稳定性、IPC 定义变更、跨平台测试（Windows/Mac/Linux）
- 典型问题：「Tauri 的 IPC 接口加了一个参数——前端调用和后端处理都要改，需要两边同时上线吗？」

## 桌面客户端特有影响维度

| 维度 | 追问 |
|------|------|
| 启动/响应速度 | 冷启动到可用要多长时间？比之前快还是慢？ |
| 系统资源 | 内存/CPU/磁盘占用变化——用户会在任务管理器/活动监视器里注意到吗？ |
| 平台原生感 | 在 Mac/Windows/Linux 上的行为是否符合各平台用户习惯？菜单、托盘、快捷键一致吗？ |
| 自动更新 | 更新是静默的还是需要用户操作？更新后配置能无缝迁移吗？ |
| IPC 可靠性 | 前端和后端的通信在异常场景（网络切换、休眠唤醒）下能否正常恢复？ |

## 典型决策场景

| 场景 | 核心影响维度 |
|------|-------------|
| Tauri 版本升级 | 跨平台兼容性 + 客户端启动性能 |
| IPC 接口变更 | 客户端开发者适配 + 插件的向前兼容 |
| 桌面集成功能（托盘/通知/快捷键） | 终端用户的操作习惯和平台原生体验 |
| 自动更新策略调整 | 终端的静默更新 vs 用户感知的更新流程 |
