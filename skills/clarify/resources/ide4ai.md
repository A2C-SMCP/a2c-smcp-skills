# Clarify — ide4ai 专属指南

> 通用流程参见 SKILL.md 主文件。

## 项目上下文

- **类型**：AI IDE MCP Server
- **语言/工具链**：Python
- **定位**：为 AI Agent 提供 IDE 内代码导航、编辑、LSP、终端操作能力——用户是使用 AI 辅助编程的开发者

## 影响视角定义

ide4ai 的「终端用户」和「开发者」高度重合——它的用户就是开发者自己。使用**定制二视角**：

| 视角 | 本项目中的含义 |
|------|---------------|
| **终端用户 = 开发者** | 在 IDE 中通过 AI 进行代码操作的人——他们既关心操作准确性（能不能找到正确的定义），也关心操作效率（比手动快多少） |
| **工具集成方** | 通过 MCP 连接 ide4ai 的 Agent 系统——它们需要理解工具的输入输出语义 |

## 关键用户画像

### 画像 1：IDE 中的 AI 用户
- 场景：在 IDE 中让 AI「找到 `handle_request` 的所有引用」「在 `config.py` 的第 42 行下面插入一段代码」
- 敏感点：符号定位的准确度（找错定义很致命）、编辑操作的精确度（插错位置要手动 undo）、终端操作的可靠性
- 典型问题：「AI 说找不到 `UserService` 的定义——但我在 IDE 里明明能跳过去。是 LSP 没启动还是索引没建好？」

### 画像 2：工具集成方开发者
- 场景：将 ide4ai 接入自己的 Agent 系统，让 Agent 能操控 IDE
- 敏感点：工具语义的稳定性、错误码的一致性和可处理性
- 典型问题：「ide4ai v0.3 的 `navigate_to_definition` 返回格式变了——我的 Agent 解析逻辑需要重写」

## IDE 特有影响维度

| 维度 | 追问 |
|------|------|
| 操作精度 | 符号定位、代码编辑的准确率——用户的信任建立在「每次都找对」上 |
| 响应延迟 | LSP 查询/代码导航的等待时间——用户切手动操作的心理阈值通常在 2-3 秒 |
| 与手动的对比 | AI 操作比手动快多少？差距不够大时用户会选择手动——「AI 帮忙」的体感优势必须可量化 |

## 典型决策场景

| 场景 | 核心影响维度 |
|------|-------------|
| LSP 集成策略调整 | 符号定位准确度 + 响应延迟——直接影响用户信任 |
| 代码编辑工具的行为变更 | 编辑精度 + 用户 undo/redo 体验 |
| 终端工具的输入输出处理 | 开发者操作的可靠性——执行失败/超时的默认行为 |
